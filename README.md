# 热搜交易所

把 60s API 的各平台热搜分别变成独立的虚拟股市。微博话题只在微博股市交易，B站、百度、抖音等市场互不合并。

## 安装

在 AstrBot WebUI 的插件管理页使用以下仓库地址安装：

```text
https://github.com/CompilError-bts/astrbot_plugin_hot_market
```

当前版本要求 AstrBot `>=4.5.7,<5`，主要功能：

- 后台按配置周期采集行情，默认 10 分钟。
- 默认启用微博、百度、B站和抖音。
- 根据同一平台内的榜单排名定价。
- 采用温和多头偏置：目标约六成在市股票上涨，强降榜股票仍会下跌。
- 排名不变或上升时产生受限的小幅上涨，溢价最多偏离排名目标价 2%。
- 使用 jieba TF-IDF 从热搜标题提取可读股票代码。
- 关键词代码冲突时自动添加稳定短后缀，旧哈希代码仍可继续交易。
- 行情图增加盘面情绪、每日标语、热度王、波动王和快捷买入提示。
- 行情图的在市总数与涨跌统计覆盖全部在榜和离榜观察股票，不受图片精选条数限制。
- 行情图片后可继续发送全部非退市股票明细；QQ 由插件分页并分批发送为多节点合并转发。
- 股票详情展示近 24 轮走势图、榜单摘要、原文链接，并可追加热搜封面图。
- 可按服务器本地时间调用群会话默认大模型生成每日成员持仓复盘。
- 支持买入、卖出、持仓和当前会话排行榜；排行与复盘只统计有成交记录的成员。
- 每轮定时采集后主动发送离榜持仓合并 @ 预警，同一股票的一次离榜周期只提醒一条消息。
- 资产查询中达到 1 万热币的金额自动使用“万”单位显示。
- 查询行情或股票详情时调用 AstrBot 当前配置的 t2i 服务绘制走势图。
- t2i 失败时自动回退为文本。
- SQLite 数据保存在 `data/plugin_data/astrbot_plugin_hot_market/`。

版本更新内容见 [CHANGELOG.md](CHANGELOG.md)。

## 配置

安装或重载插件后，在 AstrBot WebUI 中将 `api_base_url` 改成你的 60s API 根地址：

```text
https://60s.example.com
```

不要填写 `/v2/weibo` 等具体接口路径。以 `/v2` 结尾的根地址也可以自动兼容。
群聊权限通过 WebUI 中的 `allowed_group_umos` 配置：

- 每项填写完整 UMO，而不是单独的群号。
- 在目标群发送 `/sid` 可以获取当前 UMO。
- 列表为空时拒绝所有会话，避免插件意外暴露到新群。
- 填写 `*` 表示允许所有群聊，但私聊仍然禁止。
- 未授权会话不会请求行情、创建账户或执行交易。
- 账户、资产和排行榜继续按完整 UMO 隔离。

### 行情输出

- `display_count` 只控制行情图片中每个市场展示多少只精选股票；查询全部市场时，图片每个市场最多展示 5 只。
- 图片中的“在市热点”、涨跌家数和市场情绪按全部 `active + fading` 股票统计，已退市股票不计入。
- `send_full_market_text` 控制图片后是否继续发送全量行情明细，默认启用。图片渲染关闭或失败时仍会发送文字行情，避免没有响应。
- 全量明细先列在榜股票，再列尚未退市的离榜观察股票；离榜观察期间不能继续买入，但持仓仍可卖出。

QQ 全量行情不再依赖 AstrBot 的 `platform_settings.forward_threshold` 自动折叠。AstrBot 会把整段长文本放入一个转发节点，行情达到上万字符时可能被 QQ 协议端拒绝。插件现在主动生成分页节点并分批发送：

- `full_market_node_chars`：单个节点的目标字符上限，默认 1200，范围 500～2000。
- `full_market_nodes_per_forward`：单条合并转发最多包含的节点数，默认 4，范围 2～8。
- 超出单条容量时自动继续发送下一条合并转发，每个节点会标明当前页码和总页数。
- 其他平台继续按自身能力发送一条普通全量文本。

### 股票详情与资讯

- `/热市 详情 股票代码` 会先发送走势图，再发送包含标题、价格、排名、状态、近期价格、摘要和原文链接的资讯文本。
- 原文链接来自榜单数据；只要平台接口提供链接，就会在图片渲染成功时照常发送，不再只出现在文字回退路径。
- 百度等接口会提供 `desc` 摘要，百度、抖音、头条等接口会提供 `cover` 封面；不同平台字段能力不同，缺失时会显示提示并继续发送其他内容。
- `detail_cover_enabled` 控制是否追加发送榜单封面，默认启用；关闭后不影响走势图、摘要和原文链接。
- 插件不会抓取原文网页生成摘要，避免第三方页面反爬、登录墙或临时失败拖慢详情查询。

### 每日大模型复盘

在 WebUI 中配置：

- `daily_analysis_enabled`：是否启用，默认关闭。
- `daily_analysis_time`：每天发送时间，使用 `HH:MM`，按 AstrBot 服务器本地时区运行。
- `daily_analysis_member_limit`：最多分析多少名成员，默认 20。

任务只会发送到 `allowed_group_umos` 已授权且存在成交记录的群，并且只分析至少买入或卖出过一次的成员。每个群使用该 UMO 当前选择的默认聊天模型，不会写死模型名称；模型请求失败只记录日志，不影响行情采集。启用后会产生相应的模型调用量。

### 持仓股离榜预警

- `delist_alert_enabled`：是否启用持仓股离榜 @ 预警，默认启用。
- 每轮后台行情采集完成后，插件会主动检查所有“已授权且存在成交成员”的群 UMO，无需等待用户查询。
- 行情、详情、资产、排行和状态查询仍会补查当前群，覆盖主动发送失败或行情由查询触发的情况。
- 同一群的同一股票在一次离榜周期内只发送一条预警；若多人持有，会在同一条消息中统一 @。
- 主动消息发送失败会释放去重记录，下一轮定时采集或查询可以重试。
- 股票重新上榜后会自动重置预警状态，未来再次离榜时可以重新提醒。
- 关闭功能不会消耗尚未发送的预警；之后重新开启时仍可提醒。

### 股票代码

股票代码格式为“平台前缀 + 热搜关键词”，例如 `WB-小米汽车`、`DY-演唱会`。关键词由 jieba 的 TF-IDF 关键词提取生成，最长 5 个字符。若两个标题得到相同代码，后出现的股票会自动增加稳定短后缀。升级前的较长关键词代码和 `WB-1A2B3C4D` 一类旧代码会保存为别名，因此现有持仓和旧指令仍然有效。

`enabled_markets` 支持：

```text
weibo
baidu
bili
douyin
zhihu
toutiao
rednote
```

## 指令

```text
/热市 帮助
/热市 行情
/热市 行情 微博
/热市 详情 WB-小米汽车
/热市 买入 WB-小米汽车 300
/热市 卖出 WB-小米汽车 5
/热市 卖出 WB-小米汽车 全部
/热市 资产
/热市 排行
/热市 状态
/热市 刷新
```

买入指令最后一个参数表示希望投入的热币金额，插件会根据现价计算可以买到的整数股数。

## MVP 定价

同一平台榜单共有 `N` 条，热点排名为 `r`：

```text
排名强度 = ((N - r + 1) / N) ^ 1.5
目标股价 = 5 + 95 × 排名强度
```

已有股票每轮向目标价移动 40%，单轮涨跌限制为 25%。为让盘面整体保持“涨多跌少”的娱乐体验，每轮以 60% 上涨家数为软目标：同榜、升榜以及只下降一名且仍接近目标价的股票可获得小幅正向漂移；明显降榜仍按排名下跌。正向漂移最多达到当前排名目标价的 2%，不会无限脱离热搜排名。

热点离榜后每轮衰减 3%，连续离榜达到配置次数后退市至 1 热币。

不同平台的原始热度值不可直接比较，因此 MVP 只使用平台内排名定价。

## 从旧版本更新

在 AstrBot WebUI 插件管理页对本插件执行更新，或使用同一 GitHub 地址重新安装。更新前可备份插件数据目录；插件会继续使用原 SQLite 数据库，不需要手动迁移。

- `metadata.yaml` 与发布版本同步为 `0.6.1`。
- 已有持仓、订单、账户和配置保持不变。
- 新增的 `detail_cover_enabled` 默认启用；不需要详情封面时可在 WebUI 关闭。
- SQLite 会自动增加摘要与封面字段，不需要手动迁移或重建数据库。
- QQ 全量行情会自动采用分页多节点转发；两个新增配置均有安全默认值，无需手动填写。
- 已有离榜预警记录继续有效；定时采集会自动启用主动发送。
- 旧版股票代码自动登记为别名，可继续用于详情、买入和卖出。
- 更新记录按版本集中维护在 [CHANGELOG.md](CHANGELOG.md)。
